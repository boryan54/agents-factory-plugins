## 1. Форматы изображений (что реально принимает Яндекс)

### 1.1. Картинки для комбинаторных (бывшие ТГО) – основной формат РСЯ

| Тип в API (`adimages.get → Type`) | Пропорции | Размер | Где показывается |
|---|---|---|---|
| `REGULAR` («стандартное») | от **1:1** до **3:4 / 4:3** (включая 4:5, 5:4) | 450–5000 px по каждой стороне, рекомендовано ≥ 1080 | Квадратные и вертикальные блоки, лента, мобильные приложения, карточки в Telegram |
| `WIDE` («широкоформатное») | **16:9** | от 1080×607 до 5000×2812 | Широкие блоки на десктопе, видеосети, Дзен |

- Форматы JPG / PNG / GIF (у GIF берётся первый кадр). Вес до **10 МБ** (в Мастере кампаний до 4 МБ).
- Вертикальнее 3:4 (9:16, 1080×1920) для **картинок** справка НЕ принимает – это только для видео. Не заливать «сторис-формат» как картинку.
- **Смарт-центры**: для каждой картинки Директ автоматически строит 4 области под 1:1, 4:3, 3:4, 16:9 и режет под блок. Смарт-центр не гарантирует, что покажется только выбранная область – **края режутся первыми**. Задать смарт-центры вручную можно только в интерфейсе ЕПК; в API v5 полей нет.
- **Карусель** (2–10 картинок в заданном порядке) – в интерфейсе/Коммандере; в API v5 у `ads.get` есть поле `ResponsiveAdFieldNames: ["Carousel"]` (проверено 25.09.2026), но в документации `ads.add` структура карусели не описана – заливать каруселью через API пока не пытаться, читать можно.

### 1.2. Графические объявления (баннеры фиксированного размера, `FIXED_IMAGE`)

- 15 размеров в интерфейсе: 160×600, 240×400, 240×600, 300×250, 300×300, 300×500, 300×600, 320×50, 320×100, 320×480, 336×280, 480×320, 728×90, 970×250, 1000×120 (в API – 44 размера с retina-кратными, например 600×500, 960×640, 1440×960).
- Вес **до 512 КБ** (не 120 КБ – это старые статьи и баннер на поиске). HTML5 – ZIP до 512 КБ.
- Обязательно: непрозрачный фон, чёткая граница баннера (цвет рамки ≠ цвет фона), поле 65×35 px вверху под плашку «Реклама», текст контрастный. Логотип свой – можно, кнопка «Подробнее / Купить» – можно, имитация ОС/интерфейса – нельзя.
- Мы делаем баннеры только когда клиент прямо просит: комбинаторные с хорошей картинкой закрывают 90 % инвентаря РСЯ. Если делаем – минимальный пакет 300×250, 336×280, 240×400, 728×90, 300×600, 970×250, 320×100, 640×200 (retina для 320×100).

### 1.3. Видео (если есть чем заполнить)

- 5–60 с, до 100 МБ, MP4 H.264, ≥ 20 к/с, рекомендовано 1080p. Пропорции **16:9, 1:1, 9:16 (и 4:5)**. До 6 роликов в комбинаторном.
- Если своего видео нет, Директ САМ соберёт «автовидео» из картинки + заголовка + текста – значит, картинка должна выдерживать наложение текста Яндекса (см. п. 2).

### 1.4. Наш обязательный пакет на ОДИН вариант креатива

```
<концепт>-<вариант>-1x1.jpg    1080×1080   REGULAR   ← главный, без него в ленте показывается случайный кроп 16:9
<концепт>-<вариант>-16x9.jpg   1920×1080   WIDE      ← десктоп, широкие блоки
<концепт>-<вариант>-3x4.jpg    1080×1440   REGULAR   ← вертикальные карточки ленты и приложений (отдельная генерация 3:4, не кроп)
```
Все три пропорции генерируются **отдельно в chatgpt-image-2** (`aspect_ratio` 1:1 / 16:9 / 3:4) с одним и тем же сюжетом и одной и той же подписью – модель сама перекомпонует кадр под пропорцию; кроп из квадрата ломает подпись.

Вариант без квадрата – брак (ловушка из практики: у фитнес-студии обе живые картинки были только 16:9, лента резала 70 % ширины, CTR в сетях 0,83 % при 3,9 % на поиске с тем же текстом). Все три файла одного варианта грузятся в ОДНО комбинаторное объявление (`AdImageHashes: [1x1, 16x9, 3x4]`) – Яндекс сам подберёт пропорцию под блок.

## 2. Текст на картинке: сколько и какой

### 2.1. Правило Яндекса
«Логотипы, водяные знаки и тексты на изображении – рекомендуем не более **20 % площади**» (исключение: упаковка товара, скриншоты, графические баннеры). Текст должен быть контрастным и читаемым. На части площадок Яндекс **накладывает заголовок объявления поверх картинки** и в автовидео тоже – запечённый текст у края превращается в кашу.

### 2.2. Наши правила по типам креатива

| Тип креатива | Текст на картинке | Когда применять |
|---|---|---|
| **О – «оффер с подписью»** (⭐ ПО УМОЛЧАНИЮ) | **Обязательна текстовая подпись: 1 сообщение ≤ 5 слов** (оффер/выгода/название продукта) + при наличии цена/скидка (старая зачёркнута → новая) + микро-строка ≤ 8 слов. Всё вместе ≤ 20 % площади, кегль читаем на 300×250 (≥ 40 px на 1080-канве для главной строки). Подпись – в безопасной зоне (п. 2.3), не у края | Все кампании РСЯ по умолчанию: картинка должна продавать сама, даже если Яндекс покажет её без заголовка (лента, Telegram, автовидео). Пример из практики: тёмное фото студии + яркий бейдж «−50 %» + зачёркнутая старая цена |
| **Ч – «чистое фото»** | Нет текста. Только сюжет | Только как ВТОРОЙ вариант в A/B-паре («с подписью» vs «без подписи»), либо когда клиент прямо запретил текст на картинке |
| **Б – баннер `FIXED_IMAGE`** | Заголовок ≤ 5 слов + выгода/цена + кнопка + логотип (лого ≤ 10 % площади) | Только по прямой просьбе клиента |

Дополнительно:
- **Один креатив – одно сообщение.** Два оффера на картинке = ноль.
- **Цены и скидки на картинке обязаны точь-в-точь совпадать с посадочной** (модерация снимает за разницу в рубль; у скидки на сайте должна быть старая цена и срок).
- Нельзя: кнопка Play, крестик «Закрыть», ползунки, QR-код, элементы дизайна Яндекса, чужие логотипы/продукты конкурентов, контакты (телефон/адрес) на картинке, «до/после» в медицине и похудении, купюры и карты, шок, размытие/артефакты/водяные знаки, прозрачный фон, контрастная рамка вокруг всей картинки.
- **Обязательные предупреждения зашиваются в картинку самим** – Директ добавляет их только в текстовую часть:
  медицина «Имеются противопоказания, необходима консультация специалиста» ≥ 5 % площади, БАД «Не является
  лекарственным средством» ≥ 10 %, кредиты/займы ≥ 10 %, букмекеры/банкротство ≥ 7 %. Подпись с оффером и
  предупреждение вместе – повод упростить оффер до 2–3 слов.
- **Формулировки, которые Яндекс читает как обход блокировок** («без VPN», «доступ из России», «зарубежные карты») – блокировка всей группы без отклонения на модерации. Это касается и текста на картинке.

### 2.3. Безопасная зона (куда класть текст и главный объект)

Директ режет картинку под блок, края уходят первыми. Держать главный объект и весь текст в **центральных 78 % ширины и 70 % высоты**:

| Канва | Безопасная зона для текста (центр) |
|---|---|
| 1:1 1080×1080 | ширина ≤ 840 px, высота ≤ 600 px, ничего важного ближе 120 px к краю |
| 16:9 1920×1080 | ширина ≤ 1440 px (центральные 75 %), высота ≤ 340 px – сплит «панель слева, фото справа» работает лучше центра |
| 3:4 1080×1440 | ширина ≤ 840 px, текст в нижней трети, объект в центре |

Верхние 5–10 % могут закрываться плашкой «Реклама» и элементами интерфейса – туда ничего не ставить.

## 3. Что рисуем: композиция, которая кликает и продаёт

Из практики (наши кабинеты + кейсы 2025–2026):
1. **Результат на экране / в руках** – человек видит, ЧТО получит (сетка готовых картинок на ноутбуке, оживлённое фото в руках, тренер ставит технику). В тесте онлайн-сервиса «результат на экране» победил абстрактную «магию с частицами».
2. **Живой человек, похожий на ЦА, с настоящей эмоцией и дневным светом** – даёт CTR, но не всегда заявки (кейс застройщика: «девушка + рассрочка» CTR 0,66 %, 2 звонка; «рендер квартиры + рассрочка» CTR 0,37 %, 8 звонков). Поэтому в паре A/B одна картинка – человек, вторая – продукт/результат.
3. **Крупный предметный кадр** (макро рук и результата) – отличается в ленте от всего остального.
4. **Фото самого бизнеса** (интерьер студии, реальные сотрудники, реальный товар) в нишах офлайн-услуг и e-commerce бьёт любую генерацию – брать с сайта клиента и обрабатывать, а не рисовать.
5. Не работает: фиолетовый неон и «AI-градиенты» (сливаются с сотнями AI-баннеров), абстракция без продукта, стоковые улыбки в офисе, коллажи из 4 сюжетов, мелкие детали.
6. Один главный объект в центре, простой фон, насыщенный (но не кислотный) цвет, читаемость на превью 90×90 px.

## 4. Генерация через Genosai (`https://api.genosai.io`, ключ `$GENOSAI_API_KEY`)

### 4.1. Модели (публичный API, проверено `GET /v1/models` 25.09.2026)

| Модель | Кредитов | Пропорции | Для чего |
|---|---|---|---|
| `chatgpt-image-2` | 6 (1K) / 10 (2K) | 1:1, 16:9, 9:16, 4:3, 3:4 | ⭐ **ЕДИНСТВЕННАЯ модель для креативов РСЯ (правило пакета).** Только она надёжно запекает русскую подпись и держит композицию под кроп. ~2–3 мин на картинку; скорость добираем параллелизмом |
| `chatgpt-image-2-5` | 6 (1K) | + 3:2, 2:3, 21:9 | Допустимая замена, если пользователь попросил 2.5 |
| `nano-banana-2` | 8 | всё, включая **4:5, 5:4** | НЕ для креативов РСЯ. Только вспомогательно: редактирование фото клиента по референсу до подачи в chatgpt-image-2 |
| `nano-banana-2-lite` | 4 | как nano-banana-2 | Черновики концептов |
| `nano-banana-pro` | 18 (1K) | всё + 1K/2K/4K | Премиальные фото, когда 2K нужен |
| `z-image` | 1 | 1:1, 4:3, 3:4, 16:9, 9:16 | Только черновая раскадровка идей для согласования (1 кр). В кабинет такие картинки не заливать |
| `seedream-5-lite` | 5,5 | 1:1 … 21:9 | Альтернатива для фотореализма |
| `grok-imagine` | 4 | 2:3, 3:2, 1:1, 16:9, 9:16 | Люди/эмоции, быстрые |

Ловушки API: ответ в `data.result.media_urls[]` (не `output`); `createTask` слать ВСЕ сразу по одному в секунду, пул воркеров = числу задач, не ждать завершения предыдущей; 429 – читать `Retry-After`/«Try again in N seconds» и не считать попыткой; всегда resume по сохранённому `taskId` (падение скрипта = сожжённые кредиты); статус – `GET /v1/taskInfo?taskId=`. Хост только `api.genosai.io`, ключ никогда не печатать и не писать в файлы.

### 4.2. Сколько генерируем и смета (⛔ смета на утверждение ДО первой траты)

На один концепт (= одна группа объявлений):
- 2 варианта (A и B) × 3 генерации (1:1, 16:9, 3:4) = **6 картинок × 6 кр = 36 кр на группу** (chatgpt-image-2, 1K). 2K (10 кр) – только если подпись мелкая и 1K её не тянет.
- Смета: `группы × 2 варианта × 3 пропорции × 6 кр`. Пример: 4 группы → **144 кр**; черновая раскадровка сюжетов на z-image (по 1 кр) – по желанию, отдельной строкой.
- Сначала показать пользователю/клиенту таблицу «группа → вариант A / вариант B → промпт → пропорции → кредиты», дождаться «да», потом запускать.

### 4.3. Промпт (шаблон)

```
[СЮЖЕТ: кто/что, действие, где, эмоция, что видно на экране/в руках – конкретно]
[КОМПОЗИЦИЯ: single clear subject centered, keep all important elements within the central 75% of the frame, simple uncluttered background, readable as a tiny thumbnail]
[СТИЛЬ (единый на всю серию клиента – повторять слово в слово): photorealistic, natural daylight / warm studio light, brand color accent <#hex>, ...]
[ТЕКСТ: тип Ч → "no text, no letters, no logos, no watermarks, no interface elements, no buttons, no play icons"
        тип О → "Overlay text, large and centered, Russian, spelled EXACTLY: «−50 %» and «Первая тренировка 1 600 ₽» – render every Russian word exactly as written, no other text, no logos, no watermarks"]
```

Правила промпта:
- Пропорция – параметром `input.aspect_ratio`, а не словами (у `nano-banana-pro-1k` – словами, он параметр не принимает).
- Один и тот же стиль-блок во всех промптах серии клиента, иначе картинки не сложатся в один бренд.
- Подпись **запекается самой chatgpt-image-2** (текст в промпте, «render every Russian word EXACTLY as written»), в каждой из трёх пропорций отдельно. После генерации **вычитывать каждую букву** – одна опечатка = брак, перегенерация только этой картинки (resume по taskId). Запасной путь для точных цен и брендового шрифта – фото без текста + наложение рендером (HTML-шаблон со шрифтом бренда → скриншот через Playwright); применять, когда модель трижды ошиблась в цифрах.
- Референс реального фото (лицо тренера, интерьер, товар): `POST /v1/uploads` → `image_urls` + «use the reference photo one-to-one, do not alter the face/product».

### 4.4. Ревью перед заливкой (обязательный гейт)
Таблица в чат: превью 1:1 / 16:9 / 3:4 каждого варианта + проверка: текст ≤ 20 %, всё важное в безопасной зоне, цена = сайт, нет запрещённых элементов, нет AI-дефектов (пальцы, кривые буквы), картинка соответствует тексту объявления и посадочной. Без «ок» не заливать.

## 5. A/B-тест картинок – обязателен на каждое объявление

### 5.1. Правило
**Минимум две картинки (A и B) на каждый концепт/группу.** Одна картинка без альтернативы – недоделанная работа. Пара строится по одной оси различия:
- A «человек/эмоция + подпись» vs B «продукт/результат + та же подпись» – базовая пара для новой ниши;
- A «подпись-выгода» vs B «подпись-цена» – когда есть скидка (сюжет один, подпись разная);
- A «с подписью» vs B «без подписи» – только если хотим проверить само правило подписи;
- A «наше реальное фото» vs B «генерация» – для офлайн-бизнеса.
Тексты, заголовки, ссылка, быстрые ссылки, уточнения у A и B **идентичны** – тогда разница в CTR = вклад картинки.

### 5.2. Как Яндекс ротирует (почему нельзя просто «залить и смотреть»)
- Внутри одного комбинаторного объявления до 5 картинок крутятся «многоруким бандитом»: лучшие комбинации быстро забирают показы, равного сплита нет, статистика по картинке видна только в интерфейсе (срез «Изображение»), в Reports API поля нет.
- Между объявлениями группы – сначала ротация, потом система отдаёт показы самому кликабельному.
- «Эксперименты» Директа (сплит аудитории через Яндекс Аудитории) считают только конверсии и расход, требуют ≥ 200 конверсий/мес и ≥ 2 недель – для CTR картинок не подходят.

### 5.3. Наша схема (измеримая через API)
```
Группа (лимит 3 объявления)
├── Объявление A: тексты X, AdImageHashes [A-1x1, A-16x9, A-3x4]
├── Объявление B: тексты X, AdImageHashes [B-1x1, B-16x9, B-3x4]   ← отличается ТОЛЬКО картинками
└── Объявление C (опционально): тексты Y, картинка-победитель прошлой волны – тест текста
```
- Статистика по `AdId` с фильтром `AdNetworkType = AD_NETWORK` (Reports API) → CTR A vs B → z-тест для двух долей.
- Порог решения по CTR: **≥ 3 000 показов на вариант и p < 0,05**; меньше – «выборки мало», ничего не выключать.
- Финальный судья – **конверсии/CPA по цели** (заявка, оплата), не CTR: картинка-победитель по CTR может проигрывать по заявкам (кейс застройщика). Для вывода по CPA – ≥ 30 конверсий на вариант или 14 дней, что раньше. Смотреть окно 14–30 дней при редких конверсиях.
- Проигравший: `ads.suspend`, на его место – новый претендент (следующая гипотеза по той же оси). Так как SUSPENDED занимает слот, при трёх занятых слотах новый вариант вносить `ads.update` в проигравшее объявление (замена `AdImageHashes`) + `ads.resume` – AdId сохраняется, объявление уходит на модерацию автоматически.
- Срок жизни креатива в РСЯ 3–5 недель; сигнал выгорания – рост CPA на 20 % при неизменных настройках → запускать новую пару.

### 5.4. Дневник теста
В папке клиента `rsya-<ГГГГ-ММ>/`: `variants.json` (сюжеты/промпты), `images.json` (хэши), `uploaded.json` (AdId ↔ вариант, дата старта), `baseline-ctr-<дата>.txt` (CTR контроля ДО замены), `ab_report.py` (или `scripts/rsya_ab.py report`). Без зафиксированного baseline тест не считается.

## 6. Рецепты API v5 (проверены 25.09.2026)

```jsonc
// 1. Загрузка картинки (тип REGULAR/WIDE определится сам)
POST /json/v5/adimages  {"method":"add","params":{"AdImages":[{"ImageData":"<base64>","Name":"as-2026-09-P1-A-1x1"}]}}
// → AddResults[0].AdImageHash. Лимит хранилища: 1000 + 2×(активных объявлений). Name – говорящее, оно видно в срезе «Изображение».

// 2. Прочитать контрольное объявление (комбинаторное!)
POST /json/v5/ads {"method":"get","params":{"SelectionCriteria":{"Ids":[<id>]},
  "FieldNames":["Id","AdGroupId","Type","State","Status"],
  "ResponsiveAdFieldNames":["Titles","Texts","Href","BusinessId","SitelinkSetId","DisplayUrlPath","AdImages","VideoExtensions","AdExtensions","PriceExtension"]}}
// TextAdFieldNames на RESPONSIVE_AD вернёт только первый элемент каждого набора – не использовать для клонирования.
// Полный список ResponsiveAdFieldNames (ответ API 25.09.2026): AdImages, DisplayDomain, Href, FinalUrl, SitelinkSetId, Texts, Titles,
// DisplayUrlPath, DutPrefix, DutSuffix, SitelinksModeration, AdExtensions, DisplayUrlPathModeration, PriceExtension, VideoExtensions,
// ButtonExtensionModeration, BusinessId, TrackingPhoneId, ButtonExtension, ErirAdDescription, TrackingParams, Carousel. AgeLabel в get НЕТ.

// 3. Клон с другой картинкой (A/B) – ТОЛЬКО v501!
POST /json/v501/ads {"method":"add","params":{"Ads":[{"AdGroupId":<gid>,"ResponsiveAd":{
  "Titles":["..."],"Texts":["..."],"Href":"https://...","SitelinkSetId":123,"DisplayUrlPath":"...",
  "AdExtensionIds":[...], "AdImageHashes":["<B-1x1>","<B-16x9>","<B-3x4>"]}}]}}
// затем ads.moderate по новым Id. Ошибка 7001 = в группе уже 3 неархивных объявления.

// 4. Заменить картинки в проигравшем объявлении (слот занят) – v501, массив в обёртке Items
POST /json/v501/ads {"method":"update","params":{"Ads":[{"Id":<id>,"ResponsiveAd":{"AdImageHashes":{"Items":["<C-1x1>","<C-16x9>","<C-3x4>"]}}}]}}  → ads.resume

// 5. Статистика A/B (Reports API)
POST /json/v5/reports  headers: processingMode: auto, skipReportHeader/Summary: true, returnMoneyInMicros: false
{"params":{"SelectionCriteria":{"DateFrom":"...","DateTo":"...","Filter":[{"Field":"AdNetworkType","Operator":"EQUALS","Values":["AD_NETWORK"]}]},
 "FieldNames":["AdGroupId","AdId","Impressions","Clicks","Cost","Conversions"],"Goals":["<goal>"],"AttributionModels":["LYDC"],
 "ReportName":"ab_<unix>","ReportType":"CUSTOM_REPORT","DateRangeType":"CUSTOM_DATE","Format":"TSV","IncludeVAT":"YES"}}
// ReportName уникальный на каждый запрос, иначе отдаётся кэш; 201/202 – повторить через несколько секунд.

// 6. Скачать живую картинку из кабинета (для baseline/ревью)
// adimages.get → PreviewUrl вида https://direct.yandex.ru/images/direct/<num>/<hash>/x90  → 404;
// рабочая ссылка: https://avatars.mds.yandex.net/get-direct/<num>/<hash>/wx1080
```

**Ловушки, пойманные при боевой заливке 25.09.2026:**
- `ads.add` / `ads.update` с `ResponsiveAd` работают ТОЛЬКО в версии **`/json/v501/ads`** – в v5 ошибка 3500 «Объявление данного типа не поддерживается в v5, используйте v501» (get работает и в v5).
- В `ads.update` массив картинок передаётся обёрткой **`"AdImageHashes": {"Items": [...]}`** (nillable-массив), в `ads.add` – плоским списком. Плоский список в update → ошибка 8000 «не может содержать массив».
- Картинка должна быть **точной пропорции**: chatgpt-image-2 иногда отдаёт 1344×768 (это 7:4, не 16:9) – `adimages.add` отвечает 5004 «Размер изображения некорректен». Скрипт `rsya_ab.py` режет до точной пропорции автоматически (`fix_aspect`).
- Genosai **кэширует неудачу по промпту**: если `createTask` стабильно отвечает 400 «Photo generation failed» на одну и ту же связку промпт + пропорция, менять 2–3 слова в сюжете – после этого генерация проходит с первого раза. Отдельно: сюжеты массажа с «oil sheen on skin / bare back» ловят «Запрос отклонён политикой безопасности» – писать «под белым полотенцем, руки на плечах».
- После `ads.update` картинок объявление остаётся ACCEPTED/ON (перемодерация картинок идёт фоном), после `ads.add` – OFF/MODERATION 1–2 дня.

Прочие ловушки: `ExcludedSites` – поле уровня кампании (не TextCampaign), применяется атомарно, `yandex.ru`/`ya.ru` не исключаются, дедуп по `.lower()`; в `adimages.get` поле `Associated: NO` = картинка загружена, но ни к одному объявлению не привязана (так в одном кабинете неделями «висели» квадраты) – проверять после заливки; объявления РСЯ **без картинки** почти не откручиваются – проверять `AdImages.Items` у всех.

## 7. Чек-лист перед сдачей РСЯ-креативов

- [ ] На каждую группу ≥ 2 варианта картинок (A/B) с одинаковыми текстами
- [ ] У каждого варианта есть 1:1 (обязательно), 16:9, 3:4; ≥ 1080 px по короткой стороне, JPG ≤ 10 МБ
- [ ] Главный объект и текст – в центральных 78 % ширины; верхние 10 % пустые
- [ ] У КАЖДОЙ картинки есть текстовая подпись (тип О): ≤ 5 слов, ≤ 20 % площади, цены = сайт; исключение – вариант Ч только внутри A/B-пары
- [ ] Все картинки сгенерированы `chatgpt-image-2` (не другой моделью)
- [ ] Нет Play/крестиков/QR/чужих лого/контактов/«до-после»/денег/«без VPN»
- [ ] Русский текст вычитан побуквенно (если запечён), нет AI-дефектов
- [ ] Имена файлов и `Name` в `adimages.add` говорящие (`<клиент>-<дата>-<концепт>-<вариант>-<пропорция>`)
- [ ] Смета кредитов утверждена ДО генерации; превью утверждены ДО заливки
- [ ] Baseline CTR контроля зафиксирован в файле до замены
- [ ] После заливки: `adimages.get → Associated: YES`, `ads.get → AdImages.Items` у всех объявлений, статус MODERATION → через 1–2 дня ACCEPTED/ON
- [ ] В дневнике теста записаны AdId ↔ вариант и дата старта; через 7 и 14 дней – отчёт z-тестом, решение только при ≥ 3 000 показов/вариант и p < 0,05, финал – по CPA
