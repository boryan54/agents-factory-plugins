# Панель Дирика – протокол обмена

Панель (`D:\GD\1Code\Dirik-panel`, запуск – `start-panel.bat`) показывает пользователю статистику и колонку
«Дирик»: решения, вопросы брифа, сделанное, уроки. Общение идёт через два файла в папке клиента,
рядом с `card.md`.

## Правило одного писателя
- `dirik.json` пишет **только Дирик**. Панель его только читает.
- `answers.json` пишет **только панель**. Дирик его только читает и никогда не меняет.

## dirik.json
```json
{
  "company": "UV-Land",
  "settings": {
    "login": "client-login",
    "goals": [{"id": null, "key": "lead_submit", "name": "Заявка с сайта", "role": "lead"},
              {"id": null, "key": "phone_click", "name": "Клик по телефону", "role": "contact"}],
    "target_cpa": null, "weekly_budget": null,
    "campaign_states": {"<CampaignId>": {"label": "дороговато", "note": "разбираюсь с площадками"}}
  },
  "items": [{"id": "q-001", "type": "question", "created": "2026-11-06", "title": "…", "text": "…",
             "why": "…", "default": "…", "status": "open"}]
}
```
- `goals`: одна или несколько целей с `role: "lead"` (главная «заявка») и вспомогательные `contact`. Пока
  `id` цели в Метрике неизвестен – `null`, панель покажет «цель не подключена».
- `target_cpa`, `weekly_budget` – без НДС, из карточки клиента.
- `type`: `decision` (решение «да/нет»), `question` (вопрос брифа), `action` (что сделал), `lesson` (урок).
- `status`: `open` – ждёт, `done` – выполнено, `closed` – закрыто без выполнения или вопрос перенесён в карточку.
- id без повторов: `d-NNN`, `q-NNN`, `a-NNN`, `l-NNN`.

## answers.json (читать в начале каждой сессии)
`{"answers": [{"id": "d-001", "answer": "yes", "at": "2026-11-06T15:04:05"}]}` – последний ответ на id главный.
Ответы: `decision` – `yes` / `no`; `question` – текст или `__default__` (принят вариант по умолчанию);
`lesson` – `read`.

## Что делать с ответами
1. **`yes` на решение** – это явное «да» на смету, записанную в этом решении. Выполни по железным правилам,
   проверь после записи, закрой решение (`status: "done"`), добавь `action` с результатом. Если цифры с момента
   записи изменились – не выполняй, а заведи новое решение с новой сметой.
2. **`no`** – закрой решение (`closed`), в `action` одной строкой: что оставил как есть.
3. **Ответ на вопрос брифа** – перенеси в `card.md` (главный источник правды о брифе), закрой вопрос
   (`closed`). `__default__` – значит принят вариант по умолчанию; в карточке пометь «допущение».
4. Не отвеченное не трогай: пользователь ответит, когда сможет.

## Как писать записи
- **Решение:** в `title` – вопрос одной фразой; в `text` – смета «что / сколько / зачем»; в `why` – почему так,
  простыми словами и с цифрами из кабинета. Это обучение пользователя: объясняй, а не командуй.
- **Вопрос:** у каждого есть `default` с пометкой «допущение» и `why` – зачем он нужен.
- **Сделал:** что именно и эффект в рублях, если он известен.
- **Урок:** 1 урок на значимое событие в кабинете, 150–300 слов, на живом примере компании. Markdown:
  `#`, `##`, абзацы, списки `-`, `**жирный**`.
- Текст по-русски, среднее тире (–), после двоеточия – строчная буква.

## Запись файла
`dirik.json` пиши целиком, валидным JSON (UTF-8). После записи проверь:
`py -3 -c "import json;json.load(open(r'<путь>\dirik.json',encoding='utf-8'))"`.
