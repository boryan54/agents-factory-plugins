## Стек агента: Wordstat за $0,16 и Вебмастер как источник истины

Для ИИ-агента главные первичные API – Yandex Search API в Yandex Cloud (бывшая XML-выдача), Wordstat API, Вебмастер, Метрика и Google Search Console. Цены Search API прозрачны: **Wordstat GetTop и GetDynamics – $0,16 за 1000 запросов**, GetRegionsDistribution – $0,41, дерево регионов бесплатно; синхронный веб-поиск – $4 днём и $3 ночью, отложенный – $0,25 и $0,21, генеративный ответ – $41,64 за 1000 запросов (без НДС) [офиц.] ([AI Studio pricing](https://aistudio.yandex.ru/docs/en/search-api/pricing); [Yandex Cloud docs](https://yandex.cloud/en/docs/search-api/concepts/wordstat)). Отложенный режим в 16 раз дешевле синхронного и подходит для съёма позиций, а генеративный ответ дорог и годится для мониторинга ИИ-присутствия на выборке ключевых запросов, а не на всём ядре. Российские LLM подешевели в разы: GigaChat Lite – 0,065 ₽ за 1000 токенов, GigaChat Pro – 0,50 ₽, YandexGPT Pro 5.1 – 0,80 ₽, YandexGPT Lite – 0,20 ₽ (октябрь 2025 – август 2026) [иссл.] ([Sostav](https://www.sostav.ru/publication/sber-i-yandeks-v-razy-snizili-stoimost-ii-generatsii-86350.html)); семейство Alice AI доступно в Yandex Cloud с ноября 2025 года ([Yandex Cloud blog](https://yandex.cloud/ru/blog/alice-ai-november-2025)). Для Wordstat появились MCP-серверы сообщества, их возможности не проверены ([mcpservers.org](https://mcpservers.org/ru/servers/askads/mcp-yandex-wordstat)); у «Тургенева» есть API, уже подключаемый через MCP.

Агентства уже собирают конвейеры на Claude Code, n8n и MCP. Один из описанных – SEO-контент-агент, который по теме, городу и профилю клиента обогащает данные, пишет текст, проверяет его по чек-листу из 80+ маркеров «ИИ-стиля» и отправляет на индексацию; так сделано около 3000 гиперлокальных страниц (20 городов × 15 услуг × 10 брендов) пачками по 50 за ночь при стоимости подписки около 15 тыс. ₽ в месяц, но результатов по трафику и лидам не опубликовано, а чек-лист маркеров устаревает [практ.] ([Sostav](https://www.sostav.ru/blogs/289407/91579)). На фоне политики scaled content abuse и статуса «маловостребованных» страниц в Яндексе такой программатик оправдан только тогда, когда каждая страница несёт уникальные локальные данные. Архитектурные принципы с Habr: LLM оркестрирует, а не читает сырой HTML, в контекст попадают только агрегаты, для сайтов от 500 тыс. URL классический краулер быстрее, для задач с SLA нужны детерминированные скрипты, а обход Cloudflare нарушает ToS [практ., автор не тестировал на живых сайтах] ([Habr](https://habr.com/p/1096874/)). Главный риск самого агента – prompt injection, прямой и через страницы конкурентов, и отравление данных; универсальной защиты нет ([Sostav/PR-CY](https://www.sostav.ru/blogs/282779/71969)), а Ahrefs отдельно предупреждает о риске инъекций через llms.txt ([Ahrefs](https://ahrefs.com/blog/llmstxt-study/)).
