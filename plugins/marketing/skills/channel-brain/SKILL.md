# channel-brain — «Мозг канала»

Один скилл — целый контент-отдел: аналитик, стратег, редактор, копирайтер. Вход всегда один: `result.json` — экспорт истории Telegram-канала.

## Источник истины
Только выгрузка канала. Каждое утверждение прослеживается до конкретных постов — ссылка вида `#id (дата)`. Чего нет в данных — того нет в отчёте.

## Шаг 0 — данные (всегда первый)

1. **Найти `result.json`.** Путь не дан — спроси. Прислали папку `ChatExport_…` — файл в её корне. Есть только `messages.html` — объясни: в Telegram Desktop повторить «Экспорт истории чата» с форматом **JSON** (HTML не парсим). Инструкция для заказчика — `references/vygruzka-kanala.md`.
2. **Прогнать парсер** (Python 3, без зависимостей, запуск через `py` на Windows):
   ```
   py <папка-скилла>/scripts/parse_export.py <путь>/result.json     # выгрузка Telegram Desktop
   py <папка-скилла>/scripts/parse_sheet.py  <путь>/канал.csv       # таблица (CSV / Google Sheets)
   ```
   Оба создают рядом с выгрузкой `channel-brain-data/`: `posts.jsonl` (нормализованные посты) и `stats.json` (ритм, топы, длины, домены), и печатают сводку.

   **Табличная выгрузка** (колонки `Ссылка · Дата · Текст · Просмотры/Реакции · Медиа`) — частый случай, когда посты собраны сторонним сервисом. Парсер чинит типовые дефекты таких таблиц: полное задвоение текста в ячейке, строки без даты. Он же определяет, какая метрика внутри.
3. **Прочитать `stats.json` целиком.** `posts.jsonl` — только выборками через `scripts/sample_posts.py` (топ по реакциям, свежие, случайные). Весь файл в контекст не тянуть.

## Куда складывать результаты
Папка проекта: `reports/` для аудитов и сравнений, `content/` для стилевых гайдов, идей, постов и свайп-файлов. Имя файла — с датой и каналом: `2026-07-30-audit-<канал>.md`.

## Режимы

| Запрос | Режим | Инструкция |
|---|---|---|
| «проанализируй мой канал», «аудит», «что заходит» | **аудит** | `references/analysis-modes.md` |
| «разбери конкурента», чужая выгрузка | **конкурент** | `references/analysis-modes.md` |
| «идеи», «контент-план», «что писать» | **идеи** | `references/analysis-modes.md` |
| «сравни каналы», 2+ выгрузки | **сравнение** | `references/analysis-modes.md` |
| «свайп-файл», «золотые посты» | **свайп** | `references/analysis-modes.md` |
| «извлеки стиль», «tone of voice» | **стиль** | `references/creation-modes.md` |
| «напиши пост как автор» | **пост** | `references/creation-modes.md` |
| «сделай из постов Reels/карусели» | **репурпозинг** | `references/creation-modes.md` |

Перед выполнением прочитай инструкцию режима в референсе — там шаги и шаблоны отчётов. Запрос общий («вот выгрузка, сделай всё») — предложи связку аудит → стиль → идеи и уточни одним вопросом, с чего начать.

**Свой канал или чужой?** Автор выгрузки — сам заказчик → «аудит». Чужой канал → «конкурент» (другой фокус: воронка, продажи, отстройка). Не очевидно — спроси, это меняет весь отчёт.

## Правила качества
- **Называй метрику ту, что есть в данных.** В JSON-экспорте Telegram это реакции (просмотров и репостов там нет). В табличной выгрузке чаще просмотры. Поле `metric` в `stats.json` говорит, какая именно; там же `metric_note`. Пиши «по просмотрам» или «по реакциям» соответственно — и никогда не подменяй одно другим.
- **Мало данных** (меньше ~30 постов) — скажи прямо, что выводы предварительные, и продолжай.
- **Каждый отчёт заканчивается блоком «Простыми словами»** — 3–5 строк без терминов: что нашли и что теперь делать. Техническую часть при этом не упрощать.
- **Тексты на выходе** пиши по стилевому гайду канала, а не среднестатистическим ИИ-текстом. Гайда нет — сначала быстрый проход режима «стиль».
- **Этика:** только публично опубликованный контент; персональных данных подписчиков в отчётах нет. Разборы — для обучения приёмам, не для дословного копирования.

## Критерии результата
✅ Парсер прогнан, выводы опираются на `#id` конкретных постов · таблицы тем/форматов со сравнением к среднему по каналу · хуки топ-постов даны цитатами, а не пересказом · есть «Простыми словами» · отчёт сохранён файлом в папку проекта.
❌ Цифры без опоры на выгрузку · «канал хороший, пишите чаще» вместо разбора · пересказ вместо цитат хуков · формула, выведенная из одного поста · отчёт только в чат, без файла.
