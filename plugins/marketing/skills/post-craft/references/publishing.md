# Публикация в Telegram-канал

## Что нужно один раз

- **Бот-издатель** — создать у @BotFather, получить токен.
- **Бот должен быть администратором канала** с правом публикации сообщений. Без этого любая отправка вернёт ошибку прав — это первая причина «не публикуется».
- **ID канала** — либо `@имя_канала` для публичного, либо числовой `-100…` для приватного.
- Токен и ID — в секреты, не в код и не в чат.

## Картинка + текст: две схемы

Картинка нужна к каждому посту, а лимиты Telegram разные, поэтому схема зависит от длины текста.

### Короткий пост (до 1024 знаков) — фото с подписью

```
POST https://api.telegram.org/bot<TOKEN>/sendPhoto
{ "chat_id": "@канал", "photo": "<URL картинки>",
  "caption": "<текст>", "parse_mode": "HTML" }
```

Просто и надёжно. **Подпись к фото — максимум 1024 знака**, это жёсткий лимит.

### Длинный пост (до 4096 знаков) — картинка через превью ссылки

Подпись не вместит длинный текст, а разбивать пост на «фото + отдельное сообщение» плохо: в ленте это два разных поста, реакции размазываются.

Решение — невидимая ссылка на картинку в начале текста. Telegram подтягивает превью и показывает изображение **над** текстом, а текст живёт по лимиту сообщения:

```
POST /sendMessage
{ "chat_id": "@канал", "parse_mode": "HTML",
  "text": "<a href=\"URL_картинки\">⁠</a><текст поста>" }
```

`⁠` — символ нулевой ширины: ссылка есть, а видимого якоря нет.

Условие: **картинка должна лежать по публичному URL**, доступному Telegram. Ссылки Genosai (`s3.genosai.io`) подходят, но если они когда-нибудь протухнут, пост останется без картинки — для важных постов надёжнее заранее положить изображение на своё хранилище.

**Лимит текста сообщения — 4096 знаков.** Не влезло — это сигнал, что пост слишком длинный для канала, а не повод резать по живому.

## Разметка

Используй **HTML** (`parse_mode: "HTML"`), не Markdown: в Markdown любой случайный `_` или `*` в тексте ломает всё сообщение, и экранировать приходится половину символов.

Поддерживаются: `<b>`, `<i>`, `<u>`, `<s>`, `<code>`, `<pre>`, `<a href>`, `<blockquote>`, спойлер через `<span class="tg-spoiler">`.

**Незакрытый тег роняет весь пост** — Telegram вернёт ошибку разбора и не отправит ничего. Проверяй парность до отправки.

## Расписание

**У Bot API нет отложенной отправки.** Планирование сообщений — функция клиента Telegram и пользовательских аккаунтов, ботам она недоступна. Значит очередь держим у себя:

1. Утверждённый пост со временем выхода кладётся в хранилище (SQLite: текст, URL картинки, время, статус).
2. Планировщик (APScheduler) в назначенное время дёргает отправку.
3. После успеха — статус `опубликован`, сохраняется `message_id`.

**Следствие:** пока служба на VPS не работает, расписание не сработает. Отсюда требования — автозапуск через `systemd` и уведомление автору, если отправка сорвалась.

## После публикации

- **`message_id` обязательно сохранять** — без него ни поправить, ни закрепить, ни собрать реакции.
- **Правка опечатки:** `editMessageText` (или `editMessageCaption` для фото с подписью). Работает только для постов, отправленных самим ботом.
- **Закрепить:** `pinChatMessage`.
- **Реакции для пост-анализа:** снимаются через `getMessageReactions`, если он доступен боту в канале; иначе — вручную от автора. Не выдумывать цифры: нет данных — так и написать.

## Частые ошибки

| Симптом | Причина |
|---|---|
| `chat not found` | неверный ID или бот не добавлен в канал |
| `not enough rights` | бот не админ или без права публикации |
| `can't parse entities` | битая HTML-разметка, незакрытый тег |
| `message is too long` | текст > 4096 или подпись > 1024 |
| `wrong file identifier / HTTP URL specified` | картинка недоступна Telegram по указанному URL |
