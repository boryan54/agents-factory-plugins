# Стандарт скилла фабрики — 7 элементов

Скилл — markdown-файл с инструкцией, который агент подгружает, когда задача совпадает с его назначением. Хороший скилл срабатывает точно в нужный момент и даёт предсказуемый результат с первого раза. Разница между хорошим и плохим — не в идее, а в структуре.

## Где живёт скилл в фабрике
Источник правды — `skills/<отдел>/<имя>/SKILL.md` (+ `references/`, `scripts/`, `feedback.md`). Плоский `plugins/` **генерируется** `build.py` — вручную туда не писать. После любой правки скилла — `python build.py`, затем внести/обновить запись в `registry/agents.yaml` (поле `skills` у агентов, что им пользуются). Имя — короткое, латиницей, через дефис.

## 7 обязательных элементов

1. **Описание с триггерами И анти-триггерами** (`description` в шапке) — что делает + дословные фразы-триггеры + «НЕ применяй для: …». Это единственное, что агент видит постоянно; тело читается только после решения разбудить скилл. 80% проблем «скилл не сработал» — слабое описание.
2. **Источник истины** — ссылка на файл/папку с данными, не копия данных внутрь. Данные меняются; скопированные — устаревают молча.
3. **Шаги отдельно, справка отдельно** — в теле короткий сценарий (5–8 шагов); объёмное (шаблоны, длинные примеры, редкие случаи) — в `references/`, на которые шаги ссылаются.
4. **Ёмкие термины вместо объяснений** — «dry-run перед реальным запуском» вместо шести строк. Знакомый термин модель подхватывает и сама перестраивает поведение.
5. **Критерии результата ✅/❌** — явный список: что считается готовым, что браком. Без них агент сдаёт первую версию; с ними — сам себя проверяет.
6. **Примеры-эталоны** — 1–2 реальных «вход → идеальный выход» из практики. Образец копируется точнее, чем описание. Нет эталона — раздел с пометкой «заполнится после первого удачного запуска».
7. **Петля обратной связи** — `feedback.md` рядом со скиллом: проколы/удачи из проектов копятся, периодически скилл обновляется по накопленному. Постуха агента фиксирует и проколы его скиллов.

## Анти-паттерны (вычищать без жалости)
- **Ад скиллов:** много скиллов, половина не вызывалась — каждый грузит описание в контекст. Лечится аудитом (мандат Аргуса при 5+ скиллах).
- **Пустые команды:** «работай качественно», «будь внимателен» — ноль информации, минус токены.
- **Дубли:** два скилла с пересекающимися триггерами — агент путается. Разводить анти-триггерами.
- **Наносы:** правки разных времён, противоречащие друг другу («в начале А, в конце Б»).

## Чек-лист (проверка за 2 минуты)
- [ ] В `description` есть: что делает + фразы-триггеры + «НЕ применяй для»
- [ ] Данные — по ссылке на источник, не скопированы
- [ ] Тело — короткие шаги; объёмное в `references/`
- [ ] Есть критерии ✅/❌
- [ ] Есть хотя бы один реальный пример «вход → эталонный выход»
- [ ] Есть петля обратной связи (`feedback.md`)
- [ ] Нет пустых команд и противоречий
- [ ] Тест триггеров: 2 фразы, на которые ДОЛЖЕН сработать + 1, на которую НЕ должен — проверено
