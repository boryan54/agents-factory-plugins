# find-skills — сначала поищи, потом пиши

Каталог [skills.sh](https://skills.sh/) — это пакетный менеджер для скиллов агентов. Прежде чем писать скилл с нуля, проверь: возможно, сообщество уже сделало его лучше, оттестировало на тысячах установок и поддерживает.

**Правило фабрики:** новый скилл своими руками пишется только после того, как поиск по каталогу ничего не дал или найденное не подошло. Причину «не подошло» называй вслух — она пойдёт в changelog.

## Инструмент

```bash
npx skills find [запрос]            # поиск по каталогу
npx skills find [запрос] --owner X  # только от конкретного автора
npx skills add <owner/repo@skill>   # установить
npx skills list                     # что уже стоит
npx skills update                   # обновить установленные
```

Нужен Node.js. Каталог с лидербордом — https://skills.sh/

## Порядок работы

1. **Пойми задачу.** Домен (тесты, дизайн, деплой, документы), конкретное действие, насколько задача типовая. Узкоспециальное вроде «разбор выгрузки нашего канала» в каталоге искать бессмысленно.
2. **Загляни в лидерборд** skills.sh — он ранжирует по установкам и сразу показывает обкатанное. Крупные источники: `vercel-labs/agent-skills`, `anthropics/skills`.
3. **Ищи через CLI**, если лидерборд не покрыл. Пробуй синонимы: не нашлось по «deploy» — попробуй «deployment» или «ci-cd».
4. **Проверь качество ДО рекомендации.** Установки: 1000+ хорошо, меньше 100 — осторожно. Источник: официальные авторы надёжнее неизвестных. Звёзды репозитория: меньше 100 — повод для скепсиса.
5. **Покажи заказчику варианты**: что делает, сколько установок, откуда, команда установки, ссылка.
6. **Ставь только после «ок».** Скилл выполняется с полными правами агента — это чужой код в твоём периметре.

## Что делать с найденным в фабрике

Каталог ставит скиллы в `.agents/skills/` или `.claude/skills/` проекта. **Для фабрики этого мало**: у нас источник правды — `skills/<отдел>/<имя>/`, откуда `build.py` собирает плагины, а `publish.py` — публичную витрину.

Поэтому найденный скилл **принимается в фабрику по стандарту**, а не копируется как есть:
1. Прочитай оригинал целиком. Чужой скилл — чужие предположения о путях, платформе и языке.
2. Оцени по `skill-standard`: есть ли триггеры и анти-триггеры, критерии результата, эталон.
3. Адаптируй: пути фабрики, русский язык, разграничение с соседними скиллами **в обе стороны**, журнал `feedback.md` рядом.
4. Сохрани ссылку на источник и автора в конце скилла и в `changelog.md` агента — чтобы через полгода было понятно, что это не наше и где смотреть обновления.
5. `python build.py`, запись в `registry/agents.yaml` тем агентам, кому скилл выдан.

Взял чужое как есть, без адаптации — оно отвалится при первом переносе в другой проект.

## Осторожность

Скилл — исполняемая инструкция с полными правами агента. Из каталога тащи только то, что прочитал глазами. Малоизвестный автор, ноль установок, инструкция, которая просит ключи или лезет за пределы проекта, — не ставим и говорим заказчику почему.

## Критерии результата
✅ Поиск сделан ДО написания своего скилла · проверены установки, источник и звёзды · заказчику показаны варианты с цифрами · установка только после «ок» · принятое в фабрику адаптировано по стандарту, с ссылкой на источник.
❌ Рекомендация по одной строке из выдачи, без проверки · копирование чужого скилла в `skills/` без адаптации · установка без согласования · написание своего скилла без попытки поискать готовый.

## Обратная связь
Проколы и удачи — в `feedback.md` рядом. Что искали и не нашли — тоже ценно: повторяющийся пробел в каталоге означает, что скилл стоит написать самим.
