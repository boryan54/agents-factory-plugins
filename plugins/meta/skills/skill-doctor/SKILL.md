# Skill Doctor — почему скилл молчит и как это починить

Диагност срабатывания. Проверяет скиллы и описания агентов фабрики по местам, где они ломаются чаще всего, и выдаёт конкретный диагноз с готовой правкой — а не общие советы.

**Главный принцип:** у скилла две независимые части, и ломаются они по-разному.

- **Frontmatter (`name`, `description`)** — решает, **запустится ли** скилл. Агент читает только это, когда выбирает, применять ли скилл. У агентов фабрики то же самое: их `description` решает, вызовут ли их как субагента.
- **Тело файла** — решает, **что произойдёт после запуска**. Читается только после срабатывания.

Первый вопрос всегда: срабатывает ли вообще? Чинить тело при сломанном описании — самая частая потеря времени.

## Где что лежит в фабрике
- Скиллы: `skills/<отдел>/<имя>/SKILL.md` (источник правды). Плоский `plugins/` генерируется `build.py`.
- Агенты: `agents/<отдел>/<имя>/<имя>.md` — их frontmatter-`description` проверяется той же методикой.
- В чужом проекте: `.claude/skills/<имя>/SKILL.md` и `.claude/agents/`.

## Шаг 1. Найти и прочитать
Назвали имя — открыть файл. Не назвали — показать список и спросить, что проверяем. Отделить frontmatter от тела: они проверяются разными правилами.

## Шаг 2. Формальное (здесь скилл умирает молча)
При любой из этих ошибок скилл не виден агенту вообще — остальное не имеет значения.

| Что проверить | Правильно | Симптом при ошибке |
|---|---|---|
| Имя файла | ровно `SKILL.md`, заглавными | скилла нет в списке |
| Расположение | `skills/<отдел>/<имя>/SKILL.md`, имя папки = `name` | нет в списке / конфликт |
| Frontmatter | `---` открыт и закрыт на отдельных строках | скилл виден, description пуст |
| `name` | латиница, нижний регистр, дефисы | виден под другим именем |
| `description` | одна строка в кавычках БЕЗ переносов (folded `>` работает в Claude Code, но однострочный — стандарт фабрики: переносим скиллы и в другие движки) | обрезка: агент видит огрызок |
| После правки | прогнан `python build.py` | плагин отстал от источника |

## Шаг 3. Разобрать description по трём частям
1. **Что делает** — одним предложением, глаголом.
2. **Когда запускать** — живые фразы заказчика (прямая речь, 4–6 штук, включая разговорные), а не пересказ функции.
3. **Когда НЕ запускать** — соседние темы с указанием, что там вместо (для фабрики — имя соседнего скилла или агента: «это Фемида, lawyer»).

**Третья часть отсутствует чаще всего.** Без неё скилл срабатывает на соседние темы, тихо делает не то и жжёт лимиты — хуже молчания, потому что незаметно. Родственные скиллы/агенты разграничиваются **в обоих файлах**, иначе побеждает случайный.

Формулировки с парами «не работает / работает» — в `references/description-cookbook.md`. Читать его при выдаче правок, чтобы советы были конкретными.

## Шаг 4. Проверить тело
Только если срабатывает, но делает не то.
- **Двусмысленные шаги**: «при необходимости», «если нужно», «соответствующим образом» — места, где агент выберет сам.
- **Нет «чего не делать»** — запреты работают сильнее половины инструкций.
- **Нет критерия готовности** (✅/❌ по стандарту фабрики) — агент остановится, где сочтёт нужным.
- **Инструкция смешана со справкой** — объёмное выносить в `references/`.

## Шаг 5. Пять проверочных запросов
Составить под конкретный скилл и отдать заказчику готовыми: **3 позитивных** (полная фраза, короткая, разговорная — обязан запуститься) + **2 негативных** (соседняя тема; разговор *о* предмете вместо работы — обязан промолчать). Признак срабатывания — агент явно сообщает о запуске скилла; нет сообщения — не запускался, каким бы правильным ни был ответ.

## Шаг 6. Диагноз — строго в формате
```
ДИАГНОЗ: <имя>
Симптом: <молчит / срабатывает лишний раз / делает не то / в порядке>
Причина: <конкретное место в файле>
Что исправить: <правки по строкам>
Готовое description (заменить целиком): "<полный текст>"
Проверить: 1) 2) 3) — запускают; 4) 5) — молчит.
```

## Правила
- `description` отдавать целиком готовым к вставке.
- Несколько проблем — сначала та, что мешает запуску.
- Тело без запроса не переписывать: диагностика — не редактура.
- Файл в порядке — так и сказать. Не выдумывать проблемы ради содержательного ответа.
- После правок скиллов/агентов фабрики: `python build.py`, запись в changelog агента, версия — патч-бамп.

## Критерии результата
✅ Назван симптом · причина указана строкой файла · description выдан целиком · есть 3+2 проверочных запроса · исправное названо исправным.
❌ «Сделайте описание понятнее» без готового текста · правка тела при сломанном description · выдуманные проблемы у здорового скилла.
