# Метаданные страницы — title, description, canonical, OG, иконки, JSON-LD

Справочник к `site-craft`. Открывается на шаге 5, когда пишутся `<head>` и шаблон страницы, и при правке метаданных на готовом сайте. Что именно требуется по SEO — `standards.md`; здесь **порядок работы и приоритеты**, когда метаданных много и не всё сразу.

## Порядок работы

1. Найти страницы с отсутствующими или неверными метаданными: `title`, `description`, `canonical`, Open Graph.
2. Проверить по приоритетам ниже — сначала критичное (дубли, индексация), потом остальное.
3. Свести четвёрку между собой: `title`, `description`, `canonical`, `og:url` не должны противоречить друг другу.
4. Проверить превью соцсетей **на боевом URL**, а не на `localhost` — иначе проверки нет.
5. Правки держать узкими: только метаданные, без попутного рефакторинга.

## 1. Корректность и дубли (критично)

- Метаданные страницы задаются **в одном месте**; две конкурирующие системы (шаблон и компонент) — источник дублей.
- Ни одного повторного `title`, `description`, `canonical`, `robots` в разметке.
- Значения детерминированные: никакой случайности и меняющихся от рендера к рендеру строк.
- Пользовательские и динамические строки экранируются.
- У каждой страницы есть безопасные значения по умолчанию для `title` и `description`.

## 2. Title и description (высокое)

- `title` есть у каждой страницы, до 60 знаков, единый формат по сайту (`Страница — Компания`).
- Без набивки ключами: заголовок читает человек в выдаче и во вкладке.
- `description` до 160 знаков — обязателен у всех страниц, которые ищут или которыми делятся.
- Только простой текст: без markdown, без кавычек-ёлочек внутри кавычек, без обрывов на полуслове.

## 3. Canonical и индексация (высокое)

- `canonical` указывает на предпочтительный адрес страницы (один вариант: с `www` или без, со слэшем или без).
- `noindex` — только для приватных, служебных и дублирующих страниц.
- `robots` в разметке соответствует реальному намерению: закрытая от индексации боевая страница — это потерянный трафик заказчика, открытая тестовая — мусор в выдаче.
- Превью-сборки и staging по умолчанию `noindex`.
- У постраничной навигации canonical ведёт себя корректно (страница 2 канонична сама себе, а не первой).

## 4. Карточки соцсетей (высокое)

- У всех страниц, которыми делятся: `og:title`, `og:description`, `og:image`.
- Картинки OG и Twitter — **абсолютными URL**, относительные не работают нигде.
- Размер картинки 1200×630, соотношение стабильное.
- `og:url` совпадает с `canonical`.
- `og:type` осмысленный: обычно `website`, для статей `article`.
- `twitter:card` — по умолчанию `summary_large_image`.
- Для РФ: `og:locale` = `ru_RU`; превью проверяются в тех мессенджерах, где заказчик реально распространяет ссылку (Telegram, ВКонтакте, WhatsApp), — они кэшируют картинку, повторная проверка после правки требует сброса кэша.

## 5. Иконки и манифест (среднее)

- Хотя бы одна favicon, работающая во всех браузерах; `apple-touch-icon`, когда уместно.
- Манифест валиден и подключён, если используется.
- `theme-color` задан осознанно, иначе интерфейс браузера будет спорить с сайтом.
- Пути к иконкам стабильные и кэшируемые.

## 6. Структурированные данные (среднее)

- JSON-LD добавляется, только если он отражает то, что реально есть на странице.
- **Не выдумывать рейтинги, отзывы, цены и реквизиты организации.** Это правило фабрики и одновременно требование поисковиков: разметка, не подтверждённая содержимым, ловится как обман.
- Обычно один блок разметки на страницу.
- Валидировать перед сдачей (валидатор Schema.org, а для Яндекса — его собственный валидатор микроразметки).

## 7. Локали и альтернативы (ниже среднего)

- Атрибут `lang` у `<html>` проставлен верно.
- `og:locale` — когда локализация действительно есть.
- `hreflang` добавляется, только если альтернативные страницы существуют.
- Локализованные страницы каноничны каждая внутри своей локали.

## 8. Границы вмешательства (критично)

- Правки минимальные, без рефакторинга соседнего кода.
- Не мигрировать фреймворк и не менять SEO-библиотеку без запроса.
- Работать по той схеме, которая уже принята в проекте: Metadata API в Next.js, встроенный `<head>` в Astro, ручная разметка — что стоит, то и используется.

## Перед сдачей

Сначала критичное: дубли, canonical, индексация. Затем — согласованность `title` / `description` / `canonical` / `og:url`. Превью проверено на боевом URL. Метаданные лучше скучные и стабильные, чем умные и динамические.
