# Протокол встречи из записи

Одна запись → один MD-протокол. Механику делают скрипты, смысл – агент.
Скрипты: `scripts/transcribe.py` (звук → реплики по голосам) и `scripts/build_md.py`
(реплики → протокол с заглушками смысловых разделов).

## Зависимости

| Что | Объём | Зачем |
|---|---|---|
| `ffmpeg` | системный | вынуть звук из видео |
| `faster-whisper` | ~100 МБ + модель | распознавание: `small` ~0,5 ГБ, `large-v3-turbo` ~1,6 ГБ |
| `sherpa-onnx`, `numpy` | ~30 МБ | разделение на голоса |
| модели голосов | ~47 МБ | качаются сами с GitHub-релизов sherpa-onnx при первом запуске |

Установка: `pip install faster-whisper sherpa-onnx numpy` (в контейнере Linux добавь
`--break-system-packages`). Токен HuggingFace и принятие условий pyannote **не нужны**:
сегментация pyannote 3.0 берётся в формате ONNX из релизов sherpa-onnx.

**Видеокарта.** На NVIDIA модель по умолчанию – `large-v3-turbo`. На Windows нужны
рантайм-библиотеки cuBLAS/cuDNN рядом с Python или в `PATH`; `Could not locate cudnn_ops64_9.dll` –
значит, библиотек не видно, а не «сломался Python». Подробности – в `references/levels.md` скилла
`vk-transcript`, раздел «Уровень 1». Без видеокарты скрипт сам уходит на процессор и `small`.

## Шаги

1. **Диагностика.** `ffprobe -v error -show_entries format=duration -of csv=p=0 <запись>` –
   длительность. Оцени время: процессор, `small` – около 0,45 длительности записи
   (час ≈ 25–30 мин на 2 ядрах; со всеми шагами – около половины длительности); видеокарта, `large-v3-turbo` – минуты на час.
2. **Число собеседников – спроси, если не сказано.** Это главный рычаг точности: с заданным
   числом разметка на эталоне совпала реплика в реплику, в автоматическом режиме голоса
   дробятся (на синтетическом тесте 2 голоса превратились в 3).
3. **Расшифровка:**
   ```bash
   python scripts/transcribe.py <запись> --out-dir .work --slug <ГГГГ-ММ-ДД>-<имя> --speakers <N>
   ```
   Печатает длительность, покрытие, реплики, слова, голоса, чем распознано, время работы.
   `--model large-v3-turbo` – принудительно тяжёлая модель (точнее имена и цифры, медленнее
   на процессоре в 4–6 раз). `--no-diarize` – без голосов.
4. **Кто есть кто.** Скрипт выдаёт только `S1`, `S2` в порядке первого появления. Сопоставь
   с людьми по содержанию: обращение по имени («Добрый день, Олег» – значит, второй голос
   не Олег), представление, «с моей стороны…». Нет надёжной зацепки – спроси заказчика,
   приложив две цитаты с таймкодами. По голосу не угадывай.
5. **Сборка:**
   ```bash
   python scripts/build_md.py --meta .work/<slug>.meta.json --turns .work/<slug>.turns.json \
       --out output/meetings/<slug>.md --title "<тема>" --date <дата встречи> --names "S1=…,S2=…"
   ```
   `--fix "ЧЧ:ММ:СС=S1"` – перевесить реплику на другой голос, когда по смыслу очевидно;
   правки скрипт перечисляет в шапке. Без `--date` шапка сама говорит, что в имени файла
   дата расшифровки.
6. **Смысловые разделы** заполняет агент вместо заглушек `<!-- АГЕНТ: … -->`:
   «Кратко», «Ход встречи по темам», «Договорённости», «Задачи», «Открытые вопросы»,
   и строку искажений во врезке «О точности».

## Облачный путь (только по разрешению)

Если подключён плагин transcribe-so и заказчик **прямо разрешил облако для этой записи**:
отдай файл сервису, расшифровку с разметкой голосов приведи к `turns.json`
(`[{"start": сек, "end": сек, "speaker": "S1", "text": "…"}]`, голоса `S1`, `S2`…
по порядку первого появления) и собери тем же `build_md.py` без `--meta`:
`--source <имя записи> --engine "transcribe.so (облако)" --diarization "transcribe.so"`.
Счётчики скрипт посчитает сам.

## Проверено (2026-11-01, контейнер Linux, 2 ядра, без видеокарты)

- **Живая запись, 4 собеседника** (`0-four-speakers-zh.wav` из релизов sherpa-onnx, 57 с):
  с `--speakers 4` разметка совпала с эталоном документации sherpa-onnx во всех 10 отрезках;
  автоматический режим совпал только при пороге 0,9 (он и стоит по умолчанию), при 0,5 – 10 голосов.
- **Русский синтетический диалог, 2 голоса, 74 с:** `small` на процессоре – 33 с работы,
  133 слова, 12 реплик; с `--speakers 2` верно 10 реплик из 12, ошибка – короткая вставка
  «И ещё» на стыке реплик. Типовые искажения `small`: «Малина» вместо «Марина»,
  «конференциал» вместо «конференц-зал», «в соединение» вместо «в середине».
- Из пяти моделей голоса (eres2net, campplus, titanet, resnet34) на эталоне с заданным
  числом собеседников точны eres2net и titanet; в скрипте – eres2net.
- **Подвох теста:** два голоса piper-tts (`ru_RU-dmitri`, `ru_RU-irina`) модели голоса не
  различают (сходство внутри и между голосами одинаковое). Для синтетических тестов второму
  голосу меняй тембр (`asetrate`), иначе «сломанное» разделение – артефакт теста.

## Ограничения

- Перебивки и одновременная речь – границы реплик едут, короткие вставки в 1–2 слова могут
  уйти не тому собеседнику. Агент сверяет по смыслу и отмечает спорное во врезке.
- Плохой звук (громкая связь, эхо, музыка) роняет и распознавание, и разделение.
  Это не исправляется настройками – так и докладывай.
- Одна запись за раз. Склейка нескольких частей – заранее, `ffmpeg -f concat`.
